# Hidden Rivers — Toronto Flood Risk

Studying how buried "hidden rivers" + aging/weak sewers together drive flood risk across
Toronto. The repo has two halves: an interactive **Dash visualization** (`app/`) and a
**modelling** pipeline of Jupyter notebooks (`modelling/`) that produces a GTA-wide risk
hotspot index and a flood-susceptibility model with interpretable (SHAP) drivers.

```

│   ├── main.py          #   year-slider map, historical maps, Risk Hotspots tab
│   └── hotspots.py      #   builds the Risk Hotspots tab from modelling artifacts
├── web/                 # scrollytelling story site (static — no build step)
│   ├── index.html       #   "Hidden Rivers" interactive scroll story
│   ├── main.js · style.css
│   ├── rivers-data.js   #   generated from the Lost Rivers GeoJSON
│   └── tools/build_rivers_data.py
├── modelling/           # research notebooks (the model + hotspot analysis)
│   ├── notebooks/
│   │   ├── 01_build_features.ipynb      # ward × year panel + static infra features
│   │   ├── 02_hotspot_overlay.ipynb     # hidden-river × weak-sewer coincidence index
│   │   └── 03_susceptibility_model.ipynb# gradient-boosting model + SHAP drivers
│   ├── lib.py           #   shared feature-engineering helpers
│   └── requirements.txt #   modelling-only deps (scikit-learn, shap, jupyter, …)
├── pipeline/
│   └── fetch_data.py    # download all raw datasets via API
├── data/
│   ├── raw/             # source datasets (see below)
│   └── processed/       # artifacts written by the notebooks, read by the app
├── wsgi.py · Procfile   # gunicorn deploy entry

└── CLAUDE.md            # research brief
```

## Setup

```bash
pip install -r requirements.txt              # app
pip install -r modelling/requirements.txt    # modelling notebooks
```

## Data

```bash
python pipeline/fetch_data.py
```

Downloads all datasets automatically from Toronto Open Data (CKAN API), Borealis Dataverse,
and Open-Meteo ERA5 into `data/raw/`. Lost rivers require manual download if the Dataverse API
is unavailable (instructions printed to console).

```
data/raw/
├── sewers/Trunk Sewer - 4326.geojson
├── rivers/doi-10.5683-sp2-tsjsqz/.../BI_Lost_Rivers_20170705_WAMS_qgis.geojson
├── floods/
│   ├── basement-flooding-by-ward.xlsx
│   ├── city-wards-4326.geojson
│   └── flood-reporting/*.shp
└── precipitation/toronto_{daily,annual}_precip.csv   ← generated by fetch_data.py
```

**Sources:** [Toronto Open Data](https://open.toronto.ca) (sewers, wards, flood reports,
basement flooding) · [Lost Rivers — Borealis Dataverse](https://doi.org/10.5683/SP2/TSJSQZ)
(buried waterways) · [Open-Meteo ERA5](https://open-meteo.com) (precipitation) ·
[U of T Map & Data Library](http://maps.library.utoronto.ca) (historical maps).

## The story site

`web/` is a scroll-driven story of the July 16, 2024 Toronto flood: you start as a
droplet in a storm cloud, fall through the skyline, flood a Queen St E streetscape
(streetcar included), then descend into the buried-rivers map — drawn live from the
same Lost Rivers dataset the app uses — learn why the creeks were buried and what
daylighting (Zurich, London) gives back, and end on the same street reimagined with
its creek daylit and swimmable.

```bash
open web/index.html                        # works straight from the filesystem
# or via the app:  python app/main.py  →  http://127.0.0.1:8050/story
```

No build step. To refresh the embedded river data after changing the source GeoJSON:
`python web/tools/build_rivers_data.py`.

## Run the app

```bash
python app/main.py            # http://127.0.0.1:8050  (story at /story)
# or, deploy entry:  gunicorn wsgi:application
```

Three tabs:
- **Interactive Map** — year slider (1802–2022) over ward floods, neighbourhood flood reports,
  trunk sewers, lost rivers (still flowing vs buried), and annual precipitation.
- **Historical Maps** — before/after historical cartography showing which creeks were buried
  in each period.
- **Risk Hotspots** — ward choropleth toggling between the hidden-river × weak-sewer
  *coincidence index* and the *modelled flood susceptibility*, plus the top SHAP drivers.
  Falls back to a placeholder until the modelling notebooks have been run.

## Modelling

Run the notebooks in order (`01` → `02` → `03`); each writes an artifact into `data/processed/`
that the next step and the app's Risk Hotspots tab consume:

| Notebook | Output | Purpose |
|---|---|---|
| `01_build_features` | `ward_year_panel.csv`, ward-static GeoJSON | ward × year (2005–2022) flood counts + static sewer/river features + that year's rainfall |
| `02_hotspot_overlay` | `ward_risk_scores.geojson` | composite coincidence index (buried-river density × weak-sewer density × flood intensity) |
| `03_susceptibility_model` | `ward_susceptibility.csv`, `shap_importances.csv` | gradient-boosting flood model + SHAP driver importances |

**Limitations (draft):** Toronto's ward boundaries changed (44→25 wards, 2018) so the
ward/flood join is approximate; precipitation is a single city-wide series (varies in time,
not space — spatial signal comes from infrastructure features); elevation/imperviousness
features are future work (require a topography download).
