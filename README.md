# Hidden Rivers — Toronto Flood Risk

Studying how buried "hidden rivers" + aging/weak sewers together drive flood risk across
Toronto. The repo has two halves: an interactive **Dash visualization** (`app/`) and a
**modelling** pipeline of Jupyter notebooks (`modelling/`) that produces a GTA-wide risk
hotspot index and a flood-susceptibility model with interpretable (SHAP) drivers.

## Data

```bash
python pipeline/fetch_data.py
```

Downloads all datasets automatically from Toronto Open Data (CKAN API), Borealis Dataverse,
and Open-Meteo ERA5 into `data/raw/`. Lost rivers require manual download if the Dataverse API
is unavailable (instructions printed to console).

```
data/raw/
├── sewers/Trunk Sewer - 4326.geojson
├── rivers/doi-10.5683-sp2-tsjsqz/.../BI_Lost_Rivers_20170705_WAMS_qgis.geojson
├── floods/
│   ├── basement-flooding-by-ward.xlsx
│   ├── city-wards-4326.geojson
│   └── flood-reporting/*.shp
└── precipitation/toronto_{daily,annual}_precip.csv   ← generated by fetch_data.py
```

**Sources:** [Toronto Open Data](https://open.toronto.ca) (sewers, wards, flood reports,
basement flooding) · [Lost Rivers — Borealis Dataverse](https://doi.org/10.5683/SP2/TSJSQZ)
(buried waterways) · [Open-Meteo ERA5](https://open-meteo.com) (precipitation) ·
[U of T Map & Data Library](http://maps.library.utoronto.ca) (historical maps).

## The story site

`web/` is an interactive scroll story (v2 — see `docs/story-v2-spec.md`) of the
July 16, 2024 Toronto flood and the 142 years of plumbing behind it. You fall as a
droplet into the flooding Queen St E streetscape, then play through the history:

1. **Get Home** — a top-down driving mini-game that is structurally rigged: the flood
   rises along the real buried-creek alignments, a Director blocks every escape route
   (always telegraphed, never instant), and the loss screen reveals that the streets
   that failed you trace Garrison Creek.
2. **The 1882 vote** — a pressure-vote between the Parks plan and burying the creeks.
   The interface pushes you to bury them; if you insist on parks, the chamber outvotes
   you 18–3. The finale remembers your ballot.
3. **The burying years** — drive a bulldozer that shoves dirt and gravel over five
   creeks, 1 s = 1 year (1880–1930), racing a sickness meter against the population
   boom. Idle play ends in `EPIDEMIC`; winning costs the city every river it had.
4. **The century** — scroll-bound fast-forward (1930–2024) over the real Lost Rivers
   map: aging combined sewers, Hazel, and how medicine fixed the sickness while the
   pipes became the flood.
5. **The forecast** — the same history, run forward as a model. A ward choropleth of the
   **modelled flood susceptibility**, the buried-creek network laid over it (the hot wards
   ride the old valleys), a switch to the **hidden-river × weak-sewer coincidence index**
   (Toronto Centre tops it), and the ranked SHAP drivers — built live from the modelling
   artifacts in `data/processed/` (see *Modelling* below). The story site's bridge between
   the history and the case for daylighting.
6. **The daylighting run** — drive a dozer along the Garrison alignment; the crew
   behind you spawns creek and parkland while four live gauges (heat, flood risk, CSO
   cost, species) race a 120-second storm ETA.
7. The same street, daylit and swimmable, closing the loop.

Every game is skippable (autopilot), pausable (`Esc`), replayable, and
keyboard-accessible with a touch d-pad on mobile; results persist in `sessionStorage`.
While a game is running you can fast-forward straight to its ending at any point — the
floating **⏩ Skip to end** chip, the `F` key, or *Skip to the end* in the `Esc` menu hand
the game to autopilot and accelerate it to its natural finish from wherever you are.
A procedural Web-Audio score (synthesised, no asset files) crossfades a calm
contemplative bed for reading into an urgent bed for the games, with contextual SFX
(rain, thunder, engine, dozer, the burial dig); it stays muted behind a speaker toggle
until you opt in. Fact cards expand into sourced tooltips on hover/tap.

```bash
open web/index.html                        # works straight from the filesystem
# or via the app:  python app/main.py  →  http://127.0.0.1:8050/story
```

No build step; everything is vanilla JS (`web/js/` — core/audio/input/island/tips
systems plus one file per game). To refresh the embedded data: river network —
`python web/tools/build_rivers_data.py` (after changing the source GeoJSON); the predictive
ward map — `python web/tools/build_risk_data.py` (after re-running the modelling notebooks;
it reuses `rivers-data.js`'s projection so the two layers stay aligned).

### Hosting (GitHub Pages)

The story site is published publicly at **https://hugo-fuhrer.github.io/hidden-rivers/**.
`.github/workflows/deploy-pages.yml` deploys `web/` to GitHub Pages on every push to
`main` that touches the site (it can also be run by hand from the **Actions** tab). The
first run enables Pages automatically with the *GitHub Actions* source. All asset paths
are relative, so the site works unchanged under the `/hidden-rivers/` project subpath.

## Run the app

```bash
python app/main.py            # http://127.0.0.1:8050  (story at /story)
# or, deploy entry:  gunicorn wsgi:application
```

Three tabs:
- **Interactive Map** — year slider (1802–2022) over ward floods, neighbourhood flood reports,
  trunk sewers, lost rivers (still flowing vs buried), and annual precipitation.
- **Historical Maps** — before/after historical cartography showing which creeks were buried
  in each period.
- **Risk Hotspots** — ward choropleth toggling between the hidden-river × weak-sewer
  *coincidence index* and the *modelled flood susceptibility*, plus the top SHAP drivers.
  Falls back to a placeholder until the modelling notebooks have been run.

## Modelling

Run the notebooks in order (`01` → `02` → `03`); each writes an artifact into `data/processed/`
that the next step and the app's Risk Hotspots tab consume:

| Notebook | Output | Purpose |
|---|---|---|
| `01_build_features` | `ward_year_panel.csv`, ward-static GeoJSON | ward × year (2005–2022) flood counts + static sewer/river features + that year's rainfall |
| `02_hotspot_overlay` | `ward_risk_scores.geojson` | composite coincidence index (buried-river density × weak-sewer density × flood intensity) |
| `03_susceptibility_model` | `ward_susceptibility.csv`, `shap_importances.csv` | gradient-boosting flood model + SHAP driver importances |

**Limitations (draft):** Toronto's ward boundaries changed (44→25 wards, 2018) so the
ward/flood join is approximate; precipitation is a single city-wide series (varies in time,
not space — spatial signal comes from infrastructure features); elevation/imperviousness
features are future work (require a topography download).
